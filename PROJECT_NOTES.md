## Как устроено решение (данные)

Каждое задание в `data_ch1_sec*.js` — объект:
```js
{ num: 27, task: "текст задания", solution: "Шаг 1. ...\n\nШаг 2. ...", odz: "a≠3, a≠0" /* или null */, answer: "(a+3)/a" }
```
`index.html` при загрузке сливает SEC1..SEC4 в один `solvedMap` по номеру и рендерит карточку.

Формат решений — **обязательно подробный**, с явными шагами и ОДЗ у каждого
задания (даже если ОДЗ "не показалась бы важной" — просили указывать всегда).
Если будете добавлять новые главы — держите тот же стиль (см. примеры в файлах).

## Как устроен калькулятор "Решить новый пример"

`solver.py` — чистый Python (sympy), гоняется внутри браузера через Pyodide
(WebAssembly). 4 операции: `solve_reduce`, `solve_addsub`, `solve_muldiv`,
`solve_equation` — все возвращают `{steps, odz, answer}`. Диспетчер —
`solve_json(kind, payload_json)`, его дергает `solver_bridge.js` через
`pyodide.globals.get('solve_json')`.

**Важные грабли, уже пойманные (см. комментарии в самом solver.py):**
- Число/выражение, делённое на число, у sympy само "раскрывается"
  ((y-4)/3 → y/3 - 4/3) — решается через `Mul(..., evaluate=False)` и
  ручную сборку строки дроби (`_frac_str`), а не прямым делением.
- `sp.solve(..., domain=Reals)` не всегда фильтрует по вещественным корням
  надёжно — используется `sp.solveset(..., domain=S.Reals)`.
- Десятичные литералы (0.5 и т.п.) у sympy превращаются в `Float` и "заражают"
  всю дальнейшую арифметику некрасивыми `7.00000000000000` — при парсинге
  они сразу переводятся в точные дроби через `nsimplify`.
- ОДЗ для уравнения считается по знаменателям ИСХОДНЫХ частей, а не по
  результату `sp.together(left-right)` — иначе он может случайно сократить
  знаменатель и потерять ограничение (пример: x/(x-2)=2/(x-2)+1 — тождество,
  но x≠2 обязано остаться в ОДЗ).

## Что НЕ реализовано (но обсуждалось / может понадобиться)

- **Другие главы учебника** — сделана только Глава I. Если продолжать —
  повторить процесс: достать текст из PDF (`_dev_archive/scripts/` показывает
  как), написать решения в том же подробном формате, проверить через sympy
  (как `_dev_archive/scripts/verify_sec*.py`), добавить `data_ch2_*.js`.
- **Геометрия / системы уравнений / раскрытие скобок как отдельная операция** —
  калькулятор сейчас умеет только: сократить/сложить/умножить/разделить дробь,
  решить ОДНО уравнение с ОДНОЙ переменной. Системы, графики, "разложить на
  множители" отдельной кнопкой, геометрические формулы — не сделаны.
- **Загрузка примера по фото (OCR)** — было сделано (Tesseract.js офлайн),
  но снято по просьбе: на сложных страницах (дробь "в столбик", степени,
  несколько ответов в строке) обычный текстовый OCR даёт нечитаемую кашу.
  Работал прилично только на чистом печатном тексте без сложной вёрстки.
  Если возвращать — учитывать этот предел, не обещать "распознает всё".
- **Service worker** — сайт работает офлайн для решебника (обычные файлы),
  но для калькулятора первый заход всё равно должен скачать Pyodide (~30 МБ)
  через интернет один раз. Настоящий PWA-service-worker, кэширующий это
  агрессивно, не сделан — сейчас полагаемся на обычный HTTP-кэш браузера.
